# 漫镜 1.5.2 全流程审计、问题说明与修复报告

审计日期：2026-08-19
审计对象：Windows x64 桌面版 1.5.2（版本号保持 `1.5.2`）
状态：代码、生产构建、安装包和 GitHub 发布前验收已完成。

## 1. 结论

本轮没有把提示词包装成“永久锁定”或“绝不穿帮”的引擎能力。已验证实现的是工作流约束、任务级引用选择、周期重锚、分项质检与人工审核；生成式模型仍可能漂移，真实画质还受用户所选模型、素材、配额和网络状态影响。

### 已完成修复

- **只能生成第一镜**：批准后自动定位并生成下一条真正缺失的镜头；抽帧失败只记警告，不再阻塞批准；保留“继续生成第 N 镜”兜底按钮。
- **同人物跨版本变脸**：会话内绑定最早获批或当前选定的 Canonical 基准身份图；单次任务每个角色只允许一份身份基准，禁止多个历史脸图同时竞争。
- **人物审美与角度参考不足**：默认角色卡升级为“左侧大正脸大头特写 + 右侧正面/45°侧面/背面全身三视图”，并增加多角度分项质检。
- **人物、道具位置漂移**：用结构化提示词强约束左右位置、景深、朝向、手持关系、道具归属和起止状态；明确这是软约束，不是几何硬锁。
- **镜头穿帮与衔接突兀**：采用“稳定帧—单一动作—稳定帧”，复杂连续动作拆短；该策略降低穿帮概率，但不能完全消除。
- **方舟引用 400**：仅在方舟明确拒绝视频/音频网址、且任务尚未成功创建时，去掉无效引用重试一次；保留人物、场景和道具图片，避免重复创建付费任务。
- **首尾帧取舍不透明**：工作台提供 A/B 两种明确模式。A 默认身份优先，抽帧只用于质检；B 可控继承已批准上一镜尾帧构图，并叠加 Canonical 身份参考。

## 2. 七项问题、原因与修复方案

### 2.1 Canonical 身份不是“引擎永久锁定”

**错误表述**：永久锁定最早批准的 Canonical 身份图。
**原因**：代码只能控制当前任务传入哪张参考图；任务结束后内存绑定失效，长序列中模型本身仍会缓慢漂移。
**修复写法**：会话内锁定最早批准或当前选定的 Canonical 基准身份图；单一生成任务每个角色只允许一份角色基准参考。
**工程实现**：绑定键由 `taskId + identityName` 组成，绑定表只驻留当前运行会话；默认每 4 镜重新挂载同一人物卡。超过 8–12 镜必然会触发至少两次重锚，但仍需逐镜审核。

### 2.2 新增四区角色卡：大头照 + 正/侧/背三视图

**旧缺陷**：只有正脸和正面全身时，侧脸、回头、背影和大俯仰镜头缺少角度证据，容易改变脸型、发型后轮廓、体型或服装结构。“独立审核”也只是后端逻辑，不是模型原生全角度识别。
**修复写法**：默认布局为左侧大正脸特写，右侧三视图（正面全身、45°侧面全身、背面全身）。大头约束五官脸型，三视图约束多角度体型、发型和服装；极端角度仍需补充对应视图。
**工程实现**：

1. 固定 16:9 横版；左侧 35%–40%，右侧 60%–65% 竖排正→侧→背。
2. 目标输出至少 1792×1024；纯白无干扰背景、均匀平光、自然轻微 T-pose、手脚完整。
3. 提示词相对优先级：大头 1.2，三视图 1.05；服务商 guidance 建议上限 1.5。软件未伪造服务商不支持的区域权重字段。
4. 质检维度：正脸、侧面轮廓、背面轮廓、五官、头身比、服装一致性；结构检查不能冒充视觉通过。
5. 新生成并通过审核的卡片写入 `character-card-v3` 标签；旧资产继续复用，不因缺少新元数据而自动扣费重做。

### 2.3 位置与道具只能“强约束”，不能绝对锁定

**错误表述**：锁定左右位置、景深、朝向、手持关系和道具归属。
**原因**：提示词是生成条件，不是物理仿真或几何约束器。
**修复写法**：通过结构化提示词强约束上述状态，降低漂移概率，无法做到绝对锁定。
**工程实现**：重要镜头可携带用户批准的构图参考图；每 6 镜重新声明一次左右顺序、景深层、朝向、手占用和道具归属。

### 2.4 “稳定—动作—稳定”只能减少穿帮

**错误表述**：限制瞬移、复制、突然出现和无理由消失。
**原因**：复杂长镜头和多主体互动仍可能让生成模型产生物体增删、变形或瞬移。
**修复写法**：采用“稳定帧—单一动作—稳定帧”结构，减少此类穿帮。
**工程实现**：一个镜头只写一个主要身体动作；换位、拿物、转身、复杂运镜拆成短片段，并在用户审核后再继续下一镜。

### 2.5 首尾帧策略必须说明代价并允许选择

**错误表述**：不使用首尾帧生成视频，抽帧只用于质检。
**原因**：这不是纯 Bug，而是身份稳定与画面继承之间的取舍；只写“不要首尾帧”会掩盖跨镜跳变代价。
**修复方案**：

- **A · 身份优先（默认）**：不把抽取的首尾帧图片送入模型；抽帧仅用于 QA。优点是减少尾帧中漂移脸继续传播，代价是镜头衔接可能更生硬。
- **B · 可控尾帧继承**：只把已批准上一镜的质检尾帧作为构图与状态参考，同时提交当前任务 Canonical 人物卡并在提示词中声明身份优先。优点是衔接更顺，代价是仍可能继承上一镜的身份偏差。

两种模式都不会把图片自动改写为 Seedance `first_frame`；视频接口保持全能参考语义。

### 2.6 学术方案是设计参考，不是已接入模型

**错误表述**：方案“采用” ConsistentID、ContextAnyone、GEN3C、VisionReward。
**原因**：容易让人误解为软件已经加载这些独立模型。
**修复写法**：身份与质检工作流参考其学术思想；软件没有安装或调用这些模型，底层视频生成引擎仍为用户配置的火山 Seedance。

### 2.7 顺序生成、审核和方舟失败恢复

**问题**：第一镜后可能停住；待审核候选可能触发重复生成；方舟拒绝不可访问的本机/临时视频或音频 URL 时整镜失败。
**工程实现**：

1. 顺序规划只有 `review / generate / complete` 三态；只生成第一个真正缺失的镜头。
2. 待审核候选阻止重复创建付费任务；批准、按原因修改、人工批准和删除均可继续。
3. 抽帧补取最多等待 20 秒，失败不阻塞批准。
4. 只有任务创建前出现明确的引用 URL 参数错误时才剔除视频/音频引用并重试一次；已创建的任务绝不盲目重建。

## 3. 全流程检测矩阵

| 步骤 | 主要风险 | 当前处理 | 验证方式 |
|---|---|---|---|
| 启动与导航 | 安装后按钮失效、页面卡死 | 桌面直载和客户端路由；冒烟逐页检查真实 HTML | 打包 EXE 冒烟 |
| 模型配置 | Base URL、密钥、模型 ID 或请求体混用 | Seedance 使用方舟原生异步通道；Agnes/兼容接口与通用 Webhook 分开 | 路由/桌面运行时单测 |
| 剧本导入 | 标题、VO/OS、制作说明误判成人物 | 语言 Agent 为主，本地解析降级；非人物标签过滤 | 中英文剧本解析单测 |
| 资产框架 | 已有资产仍被重做 | 生图前完整库精确检索；旧资产无 `sheetVersion` 也直接复用 | 资产复用单测 |
| 人物角色卡 | 人不好看、侧背面缺证据 | 四区角色卡 + v5 审美默认技能 + 多角度质检 | 提示词、技能、尺寸和质检源码单测 |
| 人物批准 | 未审核脸直接进入视频 | 新生成角色卡进入待审核；存在待审核卡时暂停，不创建视频任务 | 审核门禁源码单测 |
| 场景与道具 | 归属和位置漂移 | Canonical 场景/道具引用 + Start/End State + 每 6 镜空间重锚 | 引用组装与提示词单测 |
| 视频请求 | 首帧模式误用、方舟 400、重复扣费 | 全能参考语义；明确 URL 错误仅创建前安全重试一次 | API 路由和桌面运行时模拟 |
| 镜头动作 | 瞬移、复制、变形、动作过载 | 稳定—单一动作—稳定；复杂动作拆镜 | 提示词源码检查 + 人工候选审核 |
| 视频质检 | 总分掩盖脸/演员/画风硬伤 | 身份、演员数、服装、审美、场景、道具、空间、镜头、灯光分项审核 | 一致性闸门单测 |
| 顺序生产 | 只生成第一镜、候选重复创建 | `review / generate / complete` 三态，只找第一条缺失镜头 | 顺序规划单测 |
| 抽帧与批准 | 解码慢导致批准卡死 | 缓存优先、补取最多 20 秒、失败不阻塞 | 源码单测 + 桌面冒烟 |
| 配音 | 摘取失败、角色音色串用 | 项目级音色基准；本地桥接与内置解码双路径 | 声音单测 + 冒烟 |
| 剪辑与交付 | 上游素材不能交接 | 项目、Canvas、专业剪辑台、音视频播放和导出链 | 打包 EXE 冒烟 |
| 安装包 | 归档损坏或产物与源码不一致 | 本机生产构建、NSIS、7-Zip 完整性、SHA256 | 本轮最终验收 |

## 4. 标准 Canonical 角色卡提示词

### 正向提示词

```text
角色标准参考卡，16:9 横向布局。画面左侧 35%–40% 放置同一角色的大正脸头肩特写：平视、严格正脸、双眼看向镜头、五官清晰完整。画面右侧 60%–65% 从上到下依次排列同一角色的正面全身、45°侧面全身、背面全身。四个区域必须是同一个人，发型、发色、服装、身高和头身比完全一致。全身人物自然标准站立，轻微 T-pose，肢体完整，手脚全部显示，不截断。纯白干净背景，无阴影干扰、无道具、无风景；平面角色渲染，均匀平光，无夸张明暗。高细节、轮廓分明，适合作为 AI 视频的 Canonical 身份与造型参考。不要水印、文字和装饰边框。大头特写承担五官身份优先级 1.2，右侧三视图承担体型、发型与服装优先级 1.05；服务商 guidance 不高于 1.5。
```

### 负向提示词

```text
多个人物，不同长相，四个区域身份不一致，侧脸畸变，背面发型或服装冲突，左右翻转不一致，肢体截断，缺手缺脚，多余手指，多余肢体，复杂背景，阴影过重，文字，水印，边框，饰品杂物，夸张动作，动态姿势，透视畸变，卡通Q版，模糊，五官崩坏，塑料皮，网红同脸，空洞眼神，僵硬表情
```

### 固定生成规则

- 比例：16:9。
- 目标输出：至少 1792×1024；若服务商原生尺寸受限，客户端统一裁切/缩放到该规格。
- 风格：跟随项目的写实、国漫、二次元或其他既定风格，四区不得混用不同渲染语言。
- 合格角色卡经用户批准后才作为当前任务 Canonical 身份参考；每 4 镜重新挂载，极端角度另补参考。

## 5. “好看”的可执行定义

“好看”不是统一网红脸，而是可解释、可审核的视觉目标：

1. 脸部结构和头身比协调，保留自然的不完全对称。
2. 眼神有焦点，眼睑、瞳孔和高光稳定并服务剧情情绪。
3. 表情自然，眉眼、面颊和嘴角能表演，避免僵笑与蜡像感。
4. 轮廓有辨识度，缩略图中也能区分角色，不用尖锥下巴和模板脸。
5. 肤色/材质干净但不过度磨皮；主光、补光与眼神光逻辑明确。
6. 年龄、职业、经历、族裔和角色气质保持可信，不被“美化”抹掉身份特征。
7. 四区视图在发型、服装结构、体型和身份上相互一致。

默认生图技能已升级至 v5，并保持 `aestheticQuality` 与六项角色卡多角度指标独立审核。

## 6. 研究来源与实际集成边界

- 火山引擎 [Seedream 4.0–5.0 提示词指南](https://www.volcengine.com/docs/82379/1829186)：参考其“主体、行为、环境 + 风格、光色、构图”的清晰自然语言方式及多参考图职责描述。
- 火山引擎 [Seedance 2.0 提示词指南](https://www.volcengine.com/docs/82379/2222480)：作为实际视频引擎提示词设计参考。
- [ConsistentID](https://arxiv.org/abs/2404.16771)：参考细粒度脸部身份信息的拆分思想。
- [ContextAnyone](https://arxiv.org/abs/2512.07328)：参考脸、发型、服装和体型上下文共同保持的思想。
- [GEN3C](https://arxiv.org/abs/2503.03751)：参考显式空间/相机状态可减少物体出现消失与空间漂移的思想。
- [VisionReward](https://arxiv.org/abs/2412.21059)：参考多维、可解释的图像和视频偏好评价。

**边界**：以上研究没有作为运行时模型接入漫镜；它们只影响提示词、引用编排和质检维度。底层视频调用仍为火山 Seedance。

## 8. 无法用离线测试保证的事项

1. 离线测试不能代替用户真实火山账号的配额、模型权限、地域 Base URL 和实时服务状态。
2. 提示词、单一参考、重锚和质检只能降低身份、位置与物品漂移概率，不能承诺 100% 不变。
3. 审美包含用户偏好。软件提供默认审美合同、分项分数、重做和人工批准，而不是宣称任何随机结果必然“好看”。
4. 复杂手部交互、高速遮挡、极端俯仰和长时连续动作仍是高风险镜头，应拆镜并补充对应角度参考。
