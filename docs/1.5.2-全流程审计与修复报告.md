# 漫镜 1.5.2 全流程审计与修复报告

审计日期：2026-08-19
审计对象：Windows x64 桌面版 1.5.2（保持版本号不变）
候选安装包：`windows-app/release/漫镜-1.5.2-全能参考-无首尾帧-x64.exe`

## 1. 结论

本轮修复了三个直接影响成片的主故障：

1. **只生成第一镜**：批准候选视频时同步抽取质检帧，解码失败或超时会阻塞批准；批准后又通过整条生产线重启来找下一镜，状态容易被审核门禁截断。现在批准不再依赖抽帧成功，并用纯函数只选择“第一个真正缺失的视频镜头”。
2. **同人物跨版本变脸**：资产库可能选择较新的同名造型，视频请求还会混入历史人物参考和一个无关人物充当“风格图”，多个身份源相互竞争。现在一个人物只有一个永久 Canonical 身份锚点，优先 `canonical > locked > ready > base`，同分时选择最早建立的资产；新版本不会自动替换旧脸。
3. **人物不好看**：旧人物提示词过长、四视图中脸部占比太小，“好看”没有可检查定义。现在改为精简自然语言和两视图选角表，并把审美拆成可审核指标，而不是只写“美女/帅哥”。

代码级、构建级和打包程序级检查均已通过；真实云端画质仍取决于用户实际选择的图像/视频模型、参考素材与服务状态，因此不能用离线测试证明每一次随机生成必然美观。本报告将已验证事实与模型能力边界分开记录。

## 3. “好看”的可执行定义

“好看”不是统一脸型，也不是磨皮。默认配置现在把它定义为六项可审核目标：

1. **比例协调**：脸部结构、头身比和大中小形状节奏协调，但保留真实不对称。
2. **眼神有焦点**：瞳孔、眼睑和高光稳定，能表达人物当前情绪。
3. **表情自然**：眉眼、嘴角和面颊能够表演，避免僵笑、空洞眼和蜡像感。
4. **轮廓清楚**：脸和发型在缩略图下仍有清晰、可记忆的剪影。
5. **材质与光线可信**：使用柔和主光、自然眼神光、干净肤色/材质和受控补光，不用过度滤镜。
6. **符合角色而非模板脸**：年龄、职业、族裔、疲劳、伤疤和生活经历不能被“网红化”；不同演员必须有不同的头骨、眉眼、鼻口、年龄节奏和主记忆点。

研究依据不是“多堆形容词”，而是：官方 Seedream 指南建议用简洁自然语言写清主体、行为、环境，再补充风格、光色和构图，并明确多张参考图各自职责；多维人类偏好研究也将审美、语义、细节、构图、身体/脸/手等拆开评估。因此本轮将默认技能版本升级为 v4，并把 `aestheticQuality` 保持为独立硬指标。

## 4. 人物、道具与空间不跑偏的策略

### 人物

- 每个身份只允许一个 Canonical 脸源；换装只改变服装、妆发和剧情状态。
- 当前已批准人物卡优先，禁止把历史版本再次加入同一个生成请求进行“平均”。
- 同时锁定脸、发型、体型和服装上下文；只锁脸不足以保证跨镜角色一致。
- 视频提示词限制大角度扭头、剧烈遮挡和并发复杂动作，减少模型在不可见区域重新猜脸。

### 道具与站位

- 记录每镜开始/结束状态：人物数量、左右位置、前中后景、朝向、哪只手拿什么、道具属于谁。
- 人物或道具只能通过画边、门、遮挡物或连续手部动作进入/离开，禁止瞬移、复制、融化、凭空出现。
- 一镜只执行一个主要身体动作；复杂剧情拆镜，不让模型同时处理换位、拿物、转身和快速运镜。

### 镜头衔接

- 使用上一镜已批准完整视频作为可选连续性参考，而不是生成首尾帧。
- 上一镜结尾与下一镜开头都保留短暂稳定状态，提示词采用“稳定—动作—稳定”。
- 运镜必须有动机且速度平滑；匹配曝光、白平衡、对比、饱和度和光线方向。
- 如果上一镜只有本机 Blob/Data URL，方舟无法读取，软件明确跳过该视频引用并依靠 Canonical 图和状态文本继续，而不是提交必然 400 的参数。

## 7. 尚不能由离线测试证明的部分

1. 没有使用用户的真实付费方舟密钥发起整部多镜云生成，因此“服务商在当前账户配额下完成全部镜头”仍需真实项目验收；本轮已通过模拟 HTTP 400 和请求体测试验证恢复逻辑。
2. 生成人物是否符合每位用户的主观审美不能由代码保证；现在提供了可解释的默认指标、唯一身份锚点和人工审核门，而不是虚假承诺 100% 同脸/必然美观。
3. 纯生成式视频模型仍可能产生手指、牙齿、遮挡和高速动作伪影。软件已通过动作拆分、状态锁定、引用去冲突和逐镜审核降低概率，失败镜头仍应按具体审核原因重做。
